# Спека: пайплайн релиза песен на YouTube

Дата: 2026-06-22
Статус: согласовано, готово к написанию плана

## Цель

Локальный пайплайн, который из обложки и mp3 собирает видео, готовое к
публикации на YouTube. Оркестрация — через `justfile`, рабочая логика —
маленькие Python-скрипты, которые вызывают `ffmpeg` через `subprocess`.

MVP делает простейший вариант: статичная картинка на всю длину песни.
Оживление картинки нейросетью (Stable Video Diffusion) и бесшовный
луп/реверс — отдельный, опциональный, более поздний этап (см. «Будущее»).

## Окружение

- MacBook Pro M3 Pro, 32 GB RAM, macOS (darwin).
- Python 3.13, just 1.51, ffmpeg 8.1.
- В MVP **нет** torch / moviepy / diffusers — только ffmpeg-обёртка.

## Модель данных: песня = постоянная папка

Каждая песня живёт в **своей постоянной папке** в `library/<slug>/` весь
жизненный цикл и никуда не перемещается. Стадия релиза — **свойство песни**
(поле в `meta.json`), а не её местоположение. Поэтому разные песни
одновременно стоят каждая на своей стадии, независимо друг от друга.

```
library/
  my-track-name/
    raw/             # свалка: всё подряд, варианты картинок. Пайплайн не трогает.
    cover.jpg        # отобранная обложка (кладёт пользователь)
    track.mp3        # песня (кладёт пользователь)
    renders/         # (на будущее) варианты анимации, копятся
    youtube.mp4      # результат build
    meta.json        # состояние песни (см. ниже)
```

В корне `library/` лежат **только папки песен**.

### meta.json

```json
{
  "title": "My Track Name",
  "slug": "my-track-name",
  "stage": "draft",
  "created": "2026-06-22"
}
```

Стадии: `draft → ready → pre-published → published`.

- `draft` — песня в работе, отбираешь обложку/аудио в `raw/`.
- `ready` — ты вручную (или командой) пометил «готово к сборке». Только эти
  песни берёт `build-all`.
- `pre-published` — `youtube.mp4` собран, ждёт загрузки на YouTube.
- `published` — выложено (твоё действие после реальной загрузки).

Переход `draft → ready` — осознанный (правишь `meta.json` руками или
отдельной командой; в MVP допускается ручная правка). Дальнейшие переходы
делают команды.

## Файлы внутри папки песни

Для сборки папка должна содержать:

- ровно один аудиофайл: `*.mp3`;
- ровно одну картинку в корне папки: `*.jpg` / `*.jpeg` / `*.png` / `*.webp`
  (картинки в `raw/` игнорируются — это свалка).

Если найдено 0 или больше одного файла любого из типов — команда
останавливается с понятной ошибкой и ничего не делает (без угадывания).

Результат сборки — `youtube.mp4` в корне папки песни.

## Команды (justfile)

Все команды, кроме `build-all` и `status`, принимают **slug** песни (имя
папки). Скрипт резолвит его в `library/<slug>/`. Если slug не найден —
ошибка со списком доступных песен.

| Команда | Действие |
|---|---|
| `just new "Name"` | Создать структуру новой песни (стадия `draft`). |
| `just build <slug>` | Собрать `youtube.mp4`, выставить `stage=pre-published`. |
| `just build-all` | Собрать все песни со `stage=ready`. |
| `just publish <slug>` | Выставить `stage=published`. |
| `just status` | Таблица всех песен и их стадий (без аргумента). |

Заготовки под будущее (в MVP не реализуются, имена резервируем):

| Команда | Назначение |
|---|---|
| `just animate <slug>` | Оживить картинку через SVD → клипы в `renders/`. |
| `just build <slug> --render renders/NNN.mp4` | Финал из выбранного клипа с лупом/реверсом вместо статики. |

## Команда `new`

`just new "My Track Name"`:

1. Сгенерировать slug из названия (нижний регистр, пробелы → дефисы,
   убрать спецсимволы).
2. Если `library/<slug>/` уже существует — ошибка (не перезаписываем).
3. Создать `library/<slug>/` и подпапку `raw/`.
4. Записать `meta.json` с `title`, `slug`, `stage:"draft"`, `created` (дата).
5. Напомнить пользователю положить `cover.*` и `track.mp3` в папку.

## Логика MVP-сборки (`build <slug>`)

1. Найти `library/<slug>/`, прочитать `meta.json`.
2. Найти единственный mp3 и единственную картинку в корне папки (правила выше).
3. Если `youtube.mp4` уже существует — стоп с предупреждением (не
   перезаписываем молча).
4. Вызвать ffmpeg: статичная картинка на всю длительность аудио → `youtube.mp4`.
5. Выставить `stage=pre-published` в `meta.json`.

`build-all`: пройти все папки в `library/`, у кого `stage=ready` — выполнить
`build`. Песни в других стадиях пропускаются (идемпотентность: после сборки
стадия становится `pre-published` и повторно не подхватывается).

Параметры ffmpeg (целевой формат под YouTube):

- холст **1920×1080** (16:9);
- картинку **вписываем целиком** (`scale` с сохранением пропорций) и
  добавляем чёрные поля (`pad`), если пропорции не 16:9. Обложку не обрезаем;
- видеокодек `libx264`, `-tune stillimage`, `-pix_fmt yuv420p`;
- аудиокодек `aac`, битрейт `320k`;
- длительность ролика = длительность аудио (`-shortest`).

Ориентировочная команда (финальные флаги уточняются в плане):

```
ffmpeg -loop 1 -framerate 2 -i COVER -i TRACK \
  -vf "scale=1920:1080:force_original_aspect_ratio=decrease,\
pad=1920:1080:(ow-iw)/2:(oh-ih)/2:color=black,format=yuv420p" \
  -c:v libx264 -tune stillimage -r 24 \
  -c:a aac -b:a 320k -shortest \
  -movflags +faststart youtube.mp4
```

## Обработка ошибок

- Slug не найден → стоп, показать список доступных песен.
- Нет/несколько mp3 или картинок в корне папки → стоп, файлы не трогаем.
- `youtube.mp4` уже существует → стоп с предупреждением (пересборка осознанна).
- `just new` для существующего slug → стоп.
- Ошибка ffmpeg → пробросить код возврата и stderr, `meta.json` не менять.

## Артефакт: базовый промпт для nano banana

Файл `prompts/nano-banana-cover.md` — шаблон промпта для генерации обложки
через nano banana (Gemini image), сразу в нужной геометрии:

- соотношение сторон **16:9**, целевой размер **1920×1080**;
- ключевой объект по центру, безопасные отступы (ничего важного ближе
  ~7–8 % к краям) — чтобы padding в пайплайне был лишь страховкой;
- плейсхолдеры для настроения/темы песни, которые ты подставляешь.

Полный текст шаблона создаётся на этапе реализации в `prompts/nano-banana-cover.md`.

## Тестирование

- Юнит-тест slug-генерации (`new`): пробелы, регистр, спецсимволы.
- Юнит-тест на поиск файлов: 0 / 1 / много mp3 и картинок; игнор `raw/`.
- Юнит-тест чтения/записи `meta.json` и смены стадии.
- Юнит-тест на сборку ffmpeg-команды (без запуска — проверяем аргументы).
- Smoke-тест: `new` → положить картинку+mp3 → `build` → проверить, что
  `youtube.mp4` создан, 1920×1080, длительность совпадает с аудио, стадия
  стала `pre-published`.

## Будущее (вне MVP)

1. `animate` — Stable Video Diffusion (img2vid-xt) на MPS, `motion_bucket_id`
   управляет интенсивностью, результат — пронумерованные клипы в `renders/`
   (варианты не перезаписываются, копятся для выбора лучшего).
2. Бесшовный луп: оригинал + реверс, повтор до длины песни, обрезка под аудио.
3. `build --render` собирает финал из выбранного клипа вместо статики.
4. Зависимости этого этапа (torch, diffusers, moviepy) подключаются отдельно,
   чтобы не утяжелять MVP.
