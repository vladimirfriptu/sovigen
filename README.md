# sovigen — конвейер релиза песен на YouTube

Инструмент ведёт песню через восемь стадий — от идеи до публикации — и
на последнем шаге собирает готовое видео для YouTube из **обложки**
(картинка) и **песни** (WAV, M4A или MP3): картинка вписывается в кадр 1920×1080,
поверх ложится аудио, на выходе — `youtube.mp4`.

Каждая песня — это постоянная папка `library/<slug>/`, а её состояние
хранится прямо рядом, в `meta.json` (поле `stage`). Никакой БД и внешних
сервисов: весь стейт — это файлы на диске.

> **Что коммитится, а что нет.** Текст песни — `meta.json`, `brief.md`,
> `lyrics.md`, `suno.md`, `cover-prompt.md`, `youtube.md`, `notes.md` —
> версионируется в гите: у него есть история, и он приезжает на любую
> машину простым `git pull`. Медиа — `track.wav` / `track.m4a` / `track.mp3`, `cover.*`,
> `youtube.mp4` — и черновая свалка `raw/` в гит не попадают
> (см. `.gitignore`): они тяжёлые и раздули бы публичный репозиторий.
> Долговременное хранение медиа — открытый вопрос, решения пока нет,
> отслеживается в issue [#1](https://github.com/vladimirfriptu/sovigen/issues/1).

## Что нужно установить

| Зависимость | Зачем | Проверка |
|-------------|-------|----------|
| **Python 3.9+** | сам CLI (только стандартная библиотека, внешних пакетов нет) | `python3 --version` |
| **ffmpeg** (+ `ffprobe`) | сборка видео и проверка результата | `ffmpeg -version` |
| **just** *(опционально)* | удобные короткие команды из `justfile` | `just --version` |
| **pytest** *(только для тестов)* | прогон тест-сьюта, ставится в `.venv` | `just test` |

Установка системных зависимостей на macOS:

```bash
brew install ffmpeg just
```

CLI написан на чистой стандартной библиотеке Python, поэтому для генерации
песен `.venv` и pytest **не нужны** — достаточно `python3` и `ffmpeg` в PATH.
Виртуальное окружение требуется только чтобы прогонять тесты.

## Установка проекта на новой машине

```bash
git clone https://github.com/vladimirfriptu/sovigen.git
cd sovigen

# опционально — окружение для тестов
just setup          # создаёт .venv и ставит pytest
# или без just:
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
```

`git clone` уже принесёт `library/` с текстами всех существующих песен
(без медиа) — докачивать аудио/обложки/видео для уже опубликованных треков
не нужно, они появляются заново только для новой песни.

## Как устроен пайплайн

Жизненный цикл песни — восемь стадий в `meta.json`:

```
idea → brief → lyrics → prompted → recorded → ready → pre-published → published
```

| Стадия | Что означает | Чей ход |
|--------|--------------|---------|
| `idea` | папка создана, тема ещё не сформулирована | Claude |
| `brief` | `brief.md` написан — о чём песня | Claude |
| `lyrics` | тексты готовы — по одному в каждом варианте | Claude |
| `prompted` | промпты для Suno готовы — по одному в каждом варианте | вы (сгенерировать все варианты и выбрать) |
| `recorded` | трек скачан и лежит в папке как `track.wav`, `track.m4a` или `track.mp3` | Claude |
| `ready` | обложка и `youtube.md` готовы, можно собирать видео | Claude |
| `pre-published` | `youtube.mp4` собран | вы (залить на YouTube) |
| `published` | видео опубликовано | — |

Переход между стадиями делает команда `advance`: она проверяет, что для
следующей стадии есть все нужные файлы, и только тогда двигает `stage`
вперёд. Стадии `prompted` и `pre-published` — это стадии, где ход за
человеком (сгенерировать в Suno, залить на YouTube); во всех остальных
следующий шаг делает Claude.

Текст и промпт пишутся сразу в трёх вариантах (`variants/a|b|c/`): каждый со
своим стилем, углом и приёмом. Выбор делается на слух после генерации в Suno —
`just choose <slug> <id>` переносит победителя в корень песни, и дальше
пайплайн работает с обычной одной песней. Проигравшие варианты остаются в
папке: это единственная память о том, какой стиль не подошёл и почему.

Внутри папки песни:

```
library/<slug>/
  meta.json                 # стейт: title, slug, stage, source, series, language, created, stage_history, variants, chosen_variant
  brief.md                  # общий разбор источника + таблица сравнения вариантов
  variants/a/               # вариант: brief.md, lyrics.md, suno.md
  variants/b/               # ещё один — другой стиль, угол и приём
  variants/c/               # и третий
  lyrics.md                 # копия выбранного варианта (кладёт choose)
  suno.md                   # копия выбранного варианта (кладёт choose)
  cover-prompt.md           # промпт для генерации обложки
  youtube.md                # заголовок/описание для YouTube
  notes.md                  # свободные заметки
  raw/                      # черновая свалка (старые версии файлов, не в гите)
  cover.jpg | cover.png     # ровно одна обложка (.jpg/.jpeg/.png/.webp) — не в гите
  track.wav | track.m4a | track.mp3  # один аудиофайл — не в гите
  youtube.mp4               # результат сборки (после build) — не в гите
```

Сборка (`build`) требует в корне папки **ровно один** аудиофайл и **ровно
одну** картинку; лишние варианты складывай в `raw/` (это же делает
`import` автоматически), иначе пайплайн честно откажется угадывать и
попросит навести порядок.

## Команды

```bash
just new "My Track Name"           # создаёт library/my-track-name (stage=idea)
                                   # поддерживает --source, --series, --language

just advance my-track-name         # двигает песню на следующую стадию,
                                   # если для неё готовы нужные файлы

just choose my-track-name b        # переносит вариант b в корень песни
                                   # (lyrics.md, suno.md), пишет chosen_variant
                                   # и style; стадию не двигает

just import my-track ~/Downloads/take.wav
                                   # кладёт скачанный файл в папку песни под
                                   # каноническим именем (track.<ext> / cover.*),
                                   # прошлый файл того же типа уходит в raw/

just build my-track-name           # собирает youtube.mp4, stage → pre-published
                                   # требует, чтобы песня была на stage=ready
just build my-track-name --static  # явно собрать со статичной обложкой
just build my-track-name --viz     # ручной эксперимент со спектром
just build-all                     # статично собирает все песни со stage=ready
just release-static my-track-name  # recorded/ready → MP4 → pre-published
just web                           # студия только на этом компьютере
just web-lan                       # студия для телефона в локальной сети

# залей youtube.mp4 на YouTube, затем:
just publish my-track-name         # stage → published

just suno my-track-name [a]        # отправляет варианты в Suno через расширение Chrome (см. ниже)

just status                        # таблица всех песен, их стадий и чьего хода ждём
just status --json                 # то же самое в JSON
```

Старой команды `ready` больше нет — её заменил `advance`, который сам
проверяет готовность и двигает песню по всем восьми стадиям, а не только
в `ready`.

## Те же команды без just

`just` — это лишь тонкая обёртка над Python-модулем. Всё то же самое:

```bash
python3 -m sovigen.cli new "My Track Name" [--source ...] [--series ...] [--language uk]
python3 -m sovigen.cli advance my-track-name
python3 -m sovigen.cli import my-track-name ~/Downloads/take.wav
python3 -m sovigen.cli build my-track-name
python3 -m sovigen.cli build my-track-name --static
python3 -m sovigen.cli build-all
python3 -m sovigen.cli publish my-track-name
python3 -m sovigen.cli suno my-track-name [variant] [--pause 30]
python3 -m sovigen.cli status [--json]

# сборка со стадии recorded/ready до предрелиза:
bash scripts/release-static.sh my-track-name
```

## Локальная загрузка и сборка видео

Запусти локальную страницу:

```bash
just web
# открой http://127.0.0.1:8765
```

Чтобы открыть студию на телефоне в той же Wi-Fi сети, выполни `just web-lan`
или `scripts/start-studio.sh`. Скрипт покажет сетевой адрес; сервер остановится
по `Ctrl+C`. Порт по умолчанию — 8765, его можно переопределить переменной
`SOVIGEN_WEB_PORT`.

### Быстрый цикл

1. На стадии `prompted` открой песню и вариант в блоке Suno. Скопируй Lyrics,
   Style и Exclude Styles в Suno, сгенерируй варианты и выбери финальную запись.
2. Загрузить MP3/M4A/WAV можно прямо в студии: выбери вариант, по которому
   записан трек. Студия импортирует его и переведёт песню в `recorded`.
3. Подготовь несколько концепций обложки, выбери одну и загрузи JPG/PNG/WebP в
   появившейся форме. Песня перейдёт в `ready`.
4. Нажми «Собрать видео». Веб соберёт MP4 со статичной обложкой и переведёт
   песню в `pre-published`.
5. В блоке «Подготовка к YouTube» скачай MP4 и скопируй по порядку заголовок,
   описание и теги из `youtube.md`.
6. Загрузи видео на YouTube вручную, затем зафиксируй публикацию командой
   `just publish <slug>`.

Если аудио и обложка уже импортированы, `just release-static <slug>` проводит
песню со стадии `recorded` или `ready` до `pre-published`: проверяет требования,
при необходимости делает переход `recorded → ready`, собирает статичное видео
и сверяет его разрешение, формат пикселей и длительность с треком. Готовое видео
затем появится в веб-разделе для скачивания. Загрузка на YouTube и команда
`just publish <slug>` остаются ручным шагом.

Максимальный размер загрузки — 160 МБ. `just web` слушает только localhost;
`just web-lan` открывает доступ в локальной сети. Не публикуй сервер напрямую в
интернет.

Видео и загруженные медиа остаются локальными и по-прежнему исключены из Git.
Студия показывает загрузки для `prompted` и `recorded`, форму сборки для `ready`
и готовые к публикации видео для `pre-published`.

## Структура кода

```
sovigen/
  cli.py            # разбор аргументов и точка входа (argparse)
  commands.py       # логика команд new/advance/import/build/build-all/publish/status
  artifacts.py      # шаблоны md-артефактов и проверка готовности стадии
  templates/         # шаблоны brief.md/lyrics.md/suno.md/cover-prompt.md/youtube.md/notes.md
  ffmpegcmd.py      # сборка ffmpeg-команд: статичное видео и вариант с линией спектра
  inputs.py         # поиск ровно одного аудио и одной картинки в папке
  meta.py           # чтение/запись meta.json, восемь стадий, переходы
  paths.py          # расположение library/ и папок песен
  suno.py           # разбор variants/<id>/{suno,lyrics}.md и отправка вариантов в Suno
  suno_bridge.py    # локальный сервер 127.0.0.1:8787, отдаёт задачи расширению
extension/          # расширение Chrome (Manifest V3, чистый JS), заполняет форму Suno
  slug.py           # slugify заголовка (Unicode-aware, сохраняет кириллицу)
scripts/
  start-studio.sh   # запуск веб-студии для телефона в локальной сети
  release-static.sh # recorded/ready → проверенный статичный MP4
library/
  <slug>/           # одна папка на песню, см. выше
knowledge/
  README.md         # карта базы: что где лежит и в каком порядке это читать
  role.md           # роль соавтора, два формата, подбор стиля, тон
  craft/            # ремесло по этапам: lyrics, suno, cover, youtube
  styles/           # карточки откалиброванных стилей
  series/           # очередь по сериям (псалмы)
  log.md            # журнал: что сработало в Suno
tests/              # pytest-сьют на каждый модуль
```

## Формат видео

1920×1080, картинка вписана целиком с чёрным padding (ничего не
обрезается), `libx264` / `yuv420p`, аудио `aac 320k`, длительность = длине
песни, `+faststart` для быстрой отдачи. Точные команды — в
`sovigen/ffmpegcmd.py`.

Основной пайплайн всегда использует **статичную обложку**. Веб, `build-all` и
`release-static` никогда не включают спектр. Для ручного эксперимента в CLI
остаётся `just build <slug> --viz`; этот флаг явно включает линию спектра и
прогресс-бар. Без флага даже сохранённое старое значение `video_style` не
меняет статичный режим.

Спектр считает все 24 кадра в секунду, поэтому такой эксперимент длится
заметно дольше и создаёт более тяжёлый файл.

Две вещи, которые в этом графе неочевидны и легко ломаются при правке:
наложение делается в RGB, а перевод в `yuv420p` стоит один раз в самом конце
(смешивание RGBA-слоя поверх YUV переставляет цветовые плоскости, и кадр
уезжает в пурпур); и диапазон явно прижимается к `tv`, иначе full-range из
JPEG протекает в поток как `yuvj420p`.

## Два режима работы: Mac и fhome-ai

Стадии, файлы и `meta.json` общие. Различается только способ, которым варианты
попадают в Suno, и откуда запускается сборка.

| | Mac (Claude Code) | fhome-ai (agent-pi), телефон |
|---|---|---|
| Тексты и промпты | скиллы `song-*` | то же |
| Варианты в Suno | `just suno <slug> [вариант]` или кнопка «Отправить в Suno» в студии: расширение Chrome заполняет форму и жмёт Create | `just web-lan`: блок Suno в студии, Lyrics, Style и Exclude Styles копируются руками (кнопки нет, расширения там нет) |
| Трек и обложка | `just import` или студия | загрузка в студии |
| Видео | `just release-static <slug>` | кнопка «Собрать видео» или `just release-static` |

Видео во всех режимах одно и то же: статичная обложка, без спектра.

Кнопка «Отправить в Suno» стоит в каждом варианте на стадии `prompted`. Студия
сама держит мост расширения, поэтому кнопка видна только пока расширение было на
связи в последние 10 секунд, то есть открыта вкладка `suno.com/create` в Chrome.
Иначе страница выглядит как на fhome-ai: только копирование полей.

Правила, чтобы режимы не мешали друг другу:

- Студия (`just web`, `just web-lan`) слушает порт 8765, мост расширения —
  `127.0.0.1:8787` (его поднимает сама студия). `just suno` тоже занимает 8787,
  поэтому одновременно с запущенной студией он выдаст понятную ошибку: отправляйте
  кнопкой в студии или остановите студию.
- Расширению нужен Chrome владельца с открытой вкладкой Suno. На машине без
  Chrome `just suno` через 20 секунд завершится ошибкой с подсказкой: там
  используйте студию.
- Расширение лежит в `extension/` и не требует сборки. В студии и в
  `release-static` расширение не участвует.

## Отправка вариантов в Suno (режим Mac)

Команда `just suno <slug> [вариант]` заполняет форму Suno из `variants/<id>/lyrics.md`
и `suno.md` и нажимает Create. Если вариант не указан, уходят все по очереди
(пауза 30 с, `--pause N` меняет её). Скачивания нет: слушать и лайкать — в самом Suno.

Работает через расширение Chrome из `extension/` и локальный мост на `127.0.0.1:8787`:

1. Откройте `chrome://extensions`, включите Developer mode, нажмите Load unpacked и выберите `extension/`.
2. В `extension/content.js` поставьте `DRY_RUN = false` (при `true` форма заполняется, но Create не нажимается).
3. Откройте `https://suno.com/create` в Chrome под своим аккаунтом и оставьте вкладку открытой.
4. Запустите `just suno <slug>`. Если появится капча, решите её в той же вкладке.
